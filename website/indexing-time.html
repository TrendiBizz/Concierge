How long does Google take to index a new website?

How long does Google take to index a new website? There is no guaranteed timeline, and no one can promise one. Some pages are picked up quickly, others wait much longer, and some are never stored. Check crawl access, canonical tags, useful content, internal links and your sitemap first, because discovery and crawling don't guarantee a page is indexed.

Ranges are typical, not promised. They vary by site, page and how often the engine crawls your site.

What "indexed" means: discovery → crawl → index

A page goes through three steps before a search engine can show it.

  1. Discovery. The engine finds the URL, through a link or a sitemap.
  2. Crawl. The engine's bot fetches the page.
  3. Index. The engine stores the page so it can come up in searches.

A URL can stall at any step, and the fix depends on which one. Orphan pages stall at discovery. Robots.txt blocks, errors and soft-404s hit at the crawl step. Noindex tags, canonical conflicts and soft-404s keep a page out at the index step.

Indexed is only the first outcome. Indexed does not mean ranked, and ranked does not mean mentioned in AI answers. These are three separate outcomes. Our AI visibility page explains all three: Indexed, Found, Mentioned.

How long Google takes, and what you can and can't speed up

For a new or low-authority URL, Google often takes days to weeks. Some URLs wait longer, and some are never indexed.

What can help:

  • Submit an XML sitemap in Search Console. It helps Google find your URLs. It does not guarantee indexing. Google's sitemap overview: https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview
  • Link to the page from other pages on your site. This gives Google a path to the URL.
  • Use Request Indexing in URL Inspection for a few important URLs. It asks Google to recrawl. It has a quota and does not guarantee indexing. Asking again and again does not make it faster. Google's guide: https://developers.google.com/search/docs/crawling-indexing/ask-google-to-recrawl
  • Remove blockers. The checklist below shows how.

What does not help:

  • IndexNow. Google ignores it.
  • The Google Indexing API. It is limited to JobPosting and BroadcastEvent (livestream) pages. It is not a shortcut for ordinary pages. Google's quickstart: https://developers.google.com/search/apis/indexing-api/v3/quickstart
  • llms.txt. It is not an indexing tool. Our llms.txt explainer covers what it does.

New website vs new page

A brand-new website has to be discovered before anything else. Google needs to find the domain, usually through links from other sites or a sitemap submitted in Search Console, and then decide which pages are worth crawling. A new page on a site Google already knows is often found through internal links and the existing sitemap, so it can be easier to reach. Neither case has a fixed timeline. If you're asking how long Google takes to index a site, the honest answer depends on crawl access, content quality and how clearly the pages link together. Use the URL Inspection tool in Google Search Console to see the status of a specific page.

How long Bing takes, and where IndexNow fits

A clean, linked page can appear in Bing within hours to a few days. Here is how to help it along.

  • Bing Webmaster Tools. Verify your site and submit your sitemap: https://www.bing.com/webmasters/help/sitemaps-3b5cf6ed
  • URL submission. Bing lets you submit individual URLs: https://www2.bing.com/webmasters/help/URL-Submission-62f2860b
  • IndexNow. This protocol tells participating search engines that a URL was added, updated or deleted. You host a key file and send a ping when pages change. It reaches Bing and participating partners only. It does not reach Google. Read the docs at https://www.indexnow.org/documentation, the FAQ at https://www.indexnow.org/faq and Bing's page at https://www.bing.com/indexnow. Bing's setup guide: https://www2.bing.com/indexnow/getstarted

IndexNow tells engines a URL changed. It does not make them index it, and it does not make it rank.

Indexing blockers checklist

If a page has waited longer than the ranges below, work through these four. Each has one check and one fix.

1. Orphan page (discovery)

  • Check: Does any other page on your site link to this URL? Is it in your sitemap?
  • Fix: Add an internal link from a relevant page that is already indexed. Add the URL to your sitemap.

2. Noindex (index)

  • Check: Look for a robots meta tag with noindex in the page head. Also look for an X-Robots-Tag: noindex HTTP header.
  • Fix: Remove the noindex, then request a recrawl.
  • Careful: If robots.txt blocks the URL, Google can't crawl the page, so it never sees the noindex tag. Google's docs say a blocked page can still appear in results if other pages link to it. If you want a page indexed, remove the block and the noindex.
  • Sources: https://developers.google.com/search/docs/crawling-indexing/block-indexing and https://developers.google.com/search/docs/crawling-indexing/robots-meta-tag

To test robots.txt access, try our robots AI check.

3. Canonical conflict (index)

  • Check: Does the page's canonical tag point at a different URL? Do several near-identical URLs compete, such as http and https, with and without a trailing slash, or tracking parameters?
  • Fix: Point each page's canonical at the version you want indexed. Use that one URL form in links and in the sitemap. Google treats canonical as a hint, so it may choose a different URL from the one you declare.
  • Sources: https://developers.google.com/search/docs/crawling-indexing/canonicalization and https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls

4. Soft-404 (crawl and index)

  • Check: A soft-404 is a page that returns HTTP 200 (OK) but looks empty or says "not found". Load the URL and check the real status code. Check for network errors too.
  • Fix: If the page is gone, return a real 404 or 410. If the page should exist, make sure it serves real content to crawlers.
  • Sources: https://developers.google.com/crawling/docs/troubleshooting/http-status-codes and https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors

How to check in Google Search Console

Search Console shows what Google knows about a URL. Two tools matter here.

URL Inspection. Paste a URL into the search bar at the top. It shows whether the URL is on Google, when it was last crawled, whether indexing is allowed and which canonical Google chose. Help: https://support.google.com/webmasters/answer/9012289

Look for "URL is on Google" at the top of the result. If it says "URL is not on Google", the details panel below gives the reason.

Page indexing report. Open Indexing, then Pages. It lists indexed URLs and, for URLs that are not indexed, the reason. Help: https://support.google.com/webmasters/answer/7445569

Each "Why pages aren't indexed" row is a reason; click it to see the affected URLs.

How to read what you see:

  • "Discovered – currently not indexed": Google knows the URL but has not crawled it yet. This may just be waiting. Check for orphan and sitemap problems, and give it time.
  • "Crawled – currently not indexed": Google fetched the page and has not stored it. Check for soft-404 and canonical problems, and for thin or duplicate content.
  • Noindex and "Duplicate" statuses: these point to the blockers above.
  • Don't read too much into it. A status is a snapshot. A clean status does not mean the page will rank.

Honest time ranges

  • Bing, linked site, with IndexNow: hours to a few days for many URLs.
  • Google, new domain or orphan URL: days to several weeks. Some URLs never get crawled.
  • Recrawl after a change: often faster than first discovery, but not instant.

If a page sits inside these ranges and has no blockers, it is probably just waiting. If it sits well outside them, or Search Console shows a blocker reason, go back to the checklist. No one can promise you a date.

FAQ

How long does Google take to index a new website?

Google doesn't give a set time, and we can't promise one. Some new sites are picked up quickly and others take much longer, and some pages are never indexed. Fix crawl access, canonical tags and internal links, submit a sitemap, then check status in Search Console.

How long does Google take to index a site after I add a new page?

It varies by site and by page, and Google gives no guarantee. A site Google already crawls often is revisited more readily than a brand-new one, but that isn't a promise. Check the page isn't blocked or set to noindex, link to it internally, and include it in your sitemap.
