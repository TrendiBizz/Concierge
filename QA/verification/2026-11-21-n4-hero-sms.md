# N4 — Hero carrier SMS and delivery state

## Cause

Carrier acceptance was discarded and the outbox immediately reported sent. Existing Twilio SMS had no StatusCallback. Handset gateways were the only non-Twilio SMS options despite the existing Hero Asterisk voice trunk.

## Fix

Add an explicitly disabled Hero Internet form-POST adapter using its published SMS API. Store durable carrier submission/provider state before contacting the provider; uncertain or crashed submissions cannot automatically resend. Hero queue acceptance does not imply delivery. Overlength messages fail explicitly rather than truncating. Stale carrier receipts become held for reconciliation. Existing Twilio callbacks are account/signature/recipient/message-bound and terminal states withstand replay/reordering. Deprecate handset transports for new commercial onboarding in the readiness guide. Add nullable schema columns and a provider/message unique index through the existing idempotent startup schema.
