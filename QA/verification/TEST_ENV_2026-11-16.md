# The documented test command did not run — 2026-11-16

## Symptom

`AGENTS.md` and `HANDOFF.md` both give the suite as:

```bash
cd api && TEST_DATABASE_URL=postgresql://postgres:pw@127.0.0.1:55433/postgres python3 -m pytest -q
```

Run verbatim in this workspace it collects **101 errors** and executes nothing.

## Cause — three separate faults stacked

1. **Wrong interpreter.** The project's dependencies live in `/Users/jo/work-staging/venv-concierge`,
   not in the `python3` on `PATH`. The system `python3` has no `asyncpg`, so 42 modules fail to
   import.
2. **`fastembed` is intentionally shimmed, and the command does not say so.** `api/app/embeddings.py`
   imports `fastembed` (a large onnx runtime), so the repo carries
   `QA/verification/shims/fastembed.py` for tests. Without `PYTHONPATH` pointing at the shims, every
   module importing `app.rag` fails.
3. **`Pillow` was imported by a test and declared nowhere.** `api/tests/test_brand_from_site.py`
   imports `PIL`; it was in neither `api/requirements.txt` nor `api/requirements-dev.txt`. Even with
   the right interpreter and the shims, collection failed with `ModuleNotFoundError: No module
   named 'PIL'`.

## Fix

- `api/requirements-dev.txt` now declares the test-only dependency:
  `Pillow>=10,<12`, with a comment saying the app itself never imports it.
- `Pillow` installed into `venv-concierge` (11.3.0).
- The working command is documented in `AGENTS.md`:

  ```bash
  cd api && PYTHONPATH="$(cd .. && pwd)/QA/verification/shims" \
    TEST_DATABASE_URL=postgresql://postgres:pw@127.0.0.1:55433/postgres \
    /Users/jo/work-staging/venv-concierge/bin/python -m pytest -q
  ```

## Proof

- Before: `python3 -m pytest -q` → `101 errors in 2.82s` (no `asyncpg`); with `venv-concierge` →
  `42 errors` (no `fastembed`); with shims → `1 error` (`No module named 'PIL'`).
- After: the command above → **1420 passed in 36.63s**.
- The one failure that survived the first repaired run — `test_no_live_secrets_committed.py` — was
  the harness git fault (`HARNESS_GIT_ENV_2026-11-16.md`), not this defect: it shells out to
  `git ls-files`. It passed under `env -u GIT_CONFIG_COUNT` and passes now that the scrub is fixed.

## Open

`venv-concierge` lives outside the repo and is undocumented beyond this record. A future session on
a new machine will hit fault 1 again. Carried in `HANDOFF.md` as a known environment convention;
the durable fix is a checked-in bootstrap script or a documented `uv`/venv path.
