## Defect found and fixed

**Cause.** The module docstring promised the report was "created, not overwritten", but `main()`
did `(OUT / f"{today}.md").write_text(...)`. The state file is saved at the end of a run, so a
second run on the same day compares against itself, reports `changed: 0`, and overwrites the
first report — destroying the day's only record of the real delta (today: 44 pages, IndexNow
pinged). Any manual re-run, retry, or an operator checking a failure would have silently replaced
evidence with "nothing changed".

**Fix.** `report_path(today)` in `scripts/seo/geo-daily.py`: the first run of a day keeps
`YYYY-MM-DD.md`; later runs get `YYYY-MM-DD-2.md`, `-3`, … Nothing is ever replaced, which is what
the docstring always claimed.

**Test.** `api/tests/test_geo_daily.py::test_second_run_on_the_same_day_does_not_overwrite_the_first_report`
creates a first report, then asserts the next path is `-2.md` and that the first file's `changed: 44`
survives.

**Proof.** `python3 -m pytest api/tests/test_geo_daily.py -q` → `7 passed`. Mutated the fix
(`report_path` returning the day file unconditionally) → the new test failed (`1 failed, 6 passed`);
restored → `7 passed` again.
