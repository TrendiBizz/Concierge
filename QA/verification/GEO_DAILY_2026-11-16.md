# GEO daily + IndexNow fingerprint defect — 2026-11-16

Scheduled daily GEO check for trendibizz.com. The check itself ran, but it exposed a defect in our
own tooling, so that was fixed, tested and documented here before the session ended.

## What the daily check measured

`python3 scripts/seo/geo-daily.py` → `QA/verification/geo-daily/2026-11-16.md`

- sitemap HTTP 200, 43 URLs; 43 pages checked, 0 failing.
- IndexNow: HTTP 200 for 43 URLs.
- Bing `site:trendibizz.com` present at position 10; **none** of the five target prompts showed
  trendibizz.com, and neither did the brand query `Trendi Concierge`.

## The defect

`- changed since last run: 43` on 2026-11-16 (43/43 pages) and `39` on 2026-11-15 (39/39) — the
whole site "changed" every day, so **every URL was re-submitted to IndexNow daily**. Bing is
entitled to treat that as spam, and the "changed" figure was useless as a signal.

Cause: the fingerprint was `len(text) + ":" + article:modified_time`.

1. Cloudflare injects a per-request bot-challenge block into HTML responses:
   `window.__CF$cv$params={r:'<16-hex ray>'...}` plus
   `/cdn-cgi/challenge-platform/scripts/jsd/main.js?ray=<same>`. The script is present on *some*
   responses only, so the byte length moves by ~370 bytes between fetches even when the page is
   byte-identical in content. Proof, same morning, same URL `/about`: state file recorded
   `14134`, a fresh `curl` returned `13764`; three consecutive fetches had three different MD5s and
   the only diff was the `ray` token.
2. `article:modified_time` is not on our pages — they carry `dateModified` in JSON-LD — so the date
   half of the fingerprint was always empty.

Net effect: a random ray token and a randomly present challenge script decided that the site had
changed, which it had not.

## Fix

`scripts/seo/geo-daily.py` — new `fingerprint(text)`:

- strips `<script>` blocks containing Cloudflare markers (`__CF$cv$params`,
  `cdn-cgi/challenge-platform`), then any residual line containing them;
- hashes the remainder with SHA-256 (first 16 hex chars);
- appends the page's own `dateModified` from the JSON-LD.

## Tests

`api/tests/test_geo_daily.py` (3 tests) — fingerprint equality across a Cloudflare script being
present/absent and across two different ray tokens; inequality on a real copy change; and
inequality plus date carry-over on a new `dateModified`.

- Green: `python3 -m pytest tests/test_geo_daily.py -q` → 3 passed.
- Mutation proof: `fingerprint` body replaced by `return str(len(text))` → the Cloudflare test and
  the `dateModified` test both fail. Restored, green again.
- Operational proof: all 43 sitemap URLs fetched twice through the fixed code path → 0 fingerprint
  mismatches, 0 stale-date fingerprints (first 43 fingerprints all carry a real
  `dateModified`, e.g. `55682be22f155fc1:2026-11-15`).
- Full suite: `1417 passed` (was 1413; +3 new tests, +1 unrelated count already in flight).
