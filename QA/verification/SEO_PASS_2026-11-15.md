## Bug found while doing it: the site said "worldwide" where it meant New Zealand (fixed)

A bulk geo rewrite had replaced the country name with "worldwide" across the site:

| Page | Was | Now |
|---|---|---|
| /terms | "governed by worldwide law", "the laws of worldwide. Courts of worldwide…", "to the fullest extent worldwide law allows" | New Zealand in all four places |
| /privacy | "operated from worldwide via trendibizz.com", "the worldwide Privacy Act 2020" | New Zealand in both |
| /sample-report | a Google impressions table with a market row labelled "worldwide" (5 impressions) | New Zealand |
| /best-ai-receptionist | h1 "How to choose the best AI receptionist **in worldwide**", the same string in the meta description, the FAQ question and the schema | location removed |
| /ai-chat-widget | an h2 whose entire text was "worldwide" | "Works in your timezone" |
| /virtual-receptionist | "AI virtual receptionist for worldwide small businesses", h2 "Built for worldwide" | reads correctly |
| /, /penetration-testing | descriptions ending "…USD $250/month. worldwide." | "…for businesses worldwide." |

This is a legal and credibility defect, not a keyword one: the terms of service named a
jurisdiction that does not exist, and the privacy policy cited "the worldwide Privacy Act 2020".

## Step 5: the guard (done)

`healthcheck.py` gained `site:pages`, which fetches the 16 commercial pages and fails on: copy under
600 words, not exactly one h1, no canonical, a meta description over 160 characters, or the broken
location wording. It reads the full document — the shared `http()` helper truncates at 4 KB for the
other checks, which made the first live run report "234 words (floor 600), 0 h1 tags" for a
1,090-word page; the read limit is now a parameter and the page check asks for 2 MB.

Tests: `api/tests/test_site_page_quality.py` (8 tests) covers each rule, each broken string, the
report wiring, and a real HTTP round-trip proving the full document is read. Mutation-checked:
unwiring the check from the report loop turns it red, and restoring the 4 KB read turns the
read-limit test red.

Live: health check now 42 ok / 1 warn (`sms:inbound`) / 0 fail, with `site:pages` green.
