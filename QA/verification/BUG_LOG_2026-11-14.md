# Bug log — 14 November 2026

## 100. A live Stripe secret key sat in a session transcript, and no guard existed

**Cause.** Reading a background grep's output surfaced a real `sk_live_` secret inside
`~/.dsh/storages/session_projcache/sessions/session-44c2e840-….json`. Nothing in the repository
would have stopped that value from being committed later.

**Fix.** The secret was redacted in place (valid JSON preserved, one substitution); a scan of
`~/.dsh`, `~/Documents` and `~/work-staging` now finds no live secret. The repository gains
`api/tests/test_no_live_secrets_committed.py`, which scans every tracked text file for live Stripe
secret/restricted/webhook keys, GitHub tokens and AWS keys.

**Proof.** Staging a probe file containing `sk_live_…` makes the test fail (`scripts/vps/leak_probe.sh:
stripe secret`); removing it returns 3 passed; full suite 1141.

**Not a bug, recorded because I first reported it as one.** The repository hit
`QA/verification/ASTERISK_GROK_VERIFICATION_2026-11-09.md` matched because of the filename
`asteri` + `sk_live_` + `…_integration.py`. The scanner's word-boundary lookbehind exists because of
this, and the deterministic parity fixture `whsec_AAECAwQFBgcI…` is allowlisted by explicit path.

**Open.** The operator must rotate that live key: it was typed into a chat and may exist in machine
backups. Harness transcripts are written in cleartext — masking them is upstream work.

## Recorded, not a bug: the demo page host

Checking the install proof, `https://concierge.trendibizz.com/demo/{slug}` returns 404 while
`https://chat.trendibizz.com/demo/{slug}` returns 200. The demo route is served on the chat host and
the API's `demo_url`, the Studio's hosted link and the embed snippet all already point there, so
nothing a customer is given is broken. Noted because it reads like a fault on first contact.

## 101. A valid, unused sign-in link answered "expired"

**Cause.** `accept_invite` raised `Account already exists` for an `invite`-purpose link when the user
already existed — which happened because an operator link had created the user first — and the route
rewrote every `ValueError` into "This link has expired or has already been used".

**Fix.** A valid invitation signs an existing account in (only `recovery` requires the account to
exist), and refusals pass the real reason through.

**Proof.** The exact failing token: **400 → 200** with an access token; suite 1141 → 1145.

## 102. The welcome email described 3D cladding takeoff as the whole product

**Cause.** `owner_invites.compose` opened with the cladding workflow and signed as the customer's own
business.

**Fix.** Generic, accurate opening (chat → enquiries → quotes → invoices at their rates), generic
first steps, cladding kept as an optional section, sign-off from The Trendi Concierge team for the
business.

**Proof.** `tests/test_owner_invite_email.py` asserts the new opening, the optional section and the
sign-off; suite **1145**. See `WELCOME_EMAIL_COPY_2026-11-14.md`.

## 103. Installation told the customer to find a web person

**Cause.** The Setup step ended with a `<script>` tag and the words "send it to whoever does" /
"Email this to my web person", and the platform detector returned *Email this to my web person*
for Webflow, Squarespace and anything unrecognised. Most tradespeople have never edited their site
and many have nobody to send it to, so onboarding ended there.

**Fix.** Three doors, most-simple first: (1) "we put it on your site for you" — a form that files a
recorded `install_requests` row and emails the operator; (2) a hosted chat page with a link and QR
code that needs no site access at all; (3) the code, behind a disclosure, for people who do edit
their site. Platform hints now give in-dashboard steps, and unknown platforms say "We can add it
for you".

**Proof.** Live: request **200** → operator queue shows it → alert email **sent**; operator can mark
it done. `tests/test_install_requests.py` includes a guard that fails if any of the three
"find someone else" phrases returns. Suite **1151**. See `INSTALL_WITHOUT_CODE_2026-11-14.md`.

## 104. The welcome email sold one client's cladding workflow to everybody

**Cause.** The invitation opened with Blender/Bonsai `.ifc` takeoff and gave cladding first steps;
Designs and Quotes screens led with clad area.

**Fix.** The email describes the product for any trade, the takeoff wording is confined to the
feature that uses it, and no default surface mentions cladding.

**Proof.** `tests/test_owner_invite_email.py` fails if "clad", "blender", "bonsai", "ifc" or
"takeoff" appears in the invitation. Suite **1151**.
