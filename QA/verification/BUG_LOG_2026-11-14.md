# Bug log — 14 November 2026

## 100. A live Stripe secret key sat in a session transcript, and no guard existed

**Cause.** Reading a background grep's output surfaced a real `sk_live_` secret inside
`~/.dsh/storages/session_projcache/sessions/session-44c2e840-….json`. Nothing in the repository
would have stopped that value from being committed later.

**Fix.** The secret was redacted in place (valid JSON preserved, one substitution); a scan of
`~/.dsh`, `~/Documents` and `~/work-staging` now finds no live secret. The repository gains
`api/tests/test_no_live_secrets_committed.py`, which scans every tracked text file for live Stripe
secret/restricted/webhook keys, GitHub tokens and AWS keys.

**Proof.** Staging a probe file containing `sk_live_…` makes the test fail (`scripts/vps/leak_probe.sh:
stripe secret`); removing it returns 3 passed; full suite 1141.

**Not a bug, recorded because I first reported it as one.** The repository hit
`QA/verification/ASTERISK_GROK_VERIFICATION_2026-11-09.md` matched because of the filename
`asteri` + `sk_live_` + `…_integration.py`. The scanner's word-boundary lookbehind exists because of
this, and the deterministic parity fixture `whsec_AAECAwQFBgcI…` is allowlisted by explicit path.

**Open.** The operator must rotate that live key: it was typed into a chat and may exist in machine
backups. Harness transcripts are written in cleartext — masking them is upstream work.

## Recorded, not a bug: the demo page host

Checking the install proof, `https://concierge.trendibizz.com/demo/{slug}` returns 404 while
`https://chat.trendibizz.com/demo/{slug}` returns 200. The demo route is served on the chat host and
the API's `demo_url`, the Studio's hosted link and the embed snippet all already point there, so
nothing a customer is given is broken. Noted because it reads like a fault on first contact.

## 101. A valid, unused sign-in link answered "expired"

**Cause.** `accept_invite` raised `Account already exists` for an `invite`-purpose link when the user
already existed — which happened because an operator link had created the user first — and the route
rewrote every `ValueError` into "This link has expired or has already been used".

**Fix.** A valid invitation signs an existing account in (only `recovery` requires the account to
exist), and refusals pass the real reason through.

**Proof.** The exact failing token: **400 → 200** with an access token; suite 1141 → 1145.

## 102. The welcome email described 3D cladding takeoff as the whole product

**Cause.** `owner_invites.compose` opened with the cladding workflow and signed as the customer's own
business.

**Fix.** Generic, accurate opening (chat → enquiries → quotes → invoices at their rates), generic
first steps, cladding kept as an optional section, sign-off from The Trendi Concierge team for the
business.

**Proof.** `tests/test_owner_invite_email.py` asserts the new opening, the optional section and the
sign-off; suite **1145**. See `WELCOME_EMAIL_COPY_2026-11-14.md`.

## 103. Installation told the customer to find a web person

**Cause.** The Setup step ended with a `<script>` tag and the words "send it to whoever does" /
"Email this to my web person", and the platform detector returned *Email this to my web person*
for Webflow, Squarespace and anything unrecognised. Most tradespeople have never edited their site
and many have nobody to send it to, so onboarding ended there.

**Fix.** Three doors, most-simple first: (1) "we put it on your site for you" — a form that files a
recorded `install_requests` row and emails the operator; (2) a hosted chat page with a link and QR
code that needs no site access at all; (3) the code, behind a disclosure, for people who do edit
their site. Platform hints now give in-dashboard steps, and unknown platforms say "We can add it
for you".

**Proof.** Live: request **200** → operator queue shows it → alert email **sent**; operator can mark
it done. `tests/test_install_requests.py` includes a guard that fails if any of the three
"find someone else" phrases returns. Suite **1151**. See `INSTALL_WITHOUT_CODE_2026-11-14.md`.

## 104. The welcome email sold one client's cladding workflow to everybody

**Cause.** The invitation opened with Blender/Bonsai `.ifc` takeoff and gave cladding first steps;
Designs and Quotes screens led with clad area.

**Fix.** The email describes the product for any trade, the takeoff wording is confined to the
feature that uses it, and no default surface mentions cladding.

**Proof.** `tests/test_owner_invite_email.py` fails if "clad", "blender", "bonsai", "ifc" or
"takeoff" appears in the invitation. Suite **1151**.

## 105. Clicking the sign-in link a second time signed the customer out of the tab they were using

**Cause.** `accept_invite` ran `DELETE FROM tenant_sessions WHERE user_id=$1` on every sign-in, so
any later redemption of the same link (refresh, or the same email on another device) killed every
live session for that user. Reproduced on ACME: `/owner/me` on the first session returned **401**
the moment the link was clicked again.

**Fix.** Signing in no longer deletes live sessions; expired ones are pruned instead.

**Proof.** ACME before: click 1 200 / click 2 200 / first session **401**. After: 200 / 200 / first
session **200**. `test_using_a_link_twice_does_not_sign_the_other_tab_out`. Suite **1153**.

## 106. A clipped link claimed to have expired

**Cause.** Every refusal was rewritten to "This link has expired or has already been used",
including a link truncated by a mail client, sending the customer to ask for a replacement link
that would be clipped identically.

**Fix.** The exchange distinguishes a token that does not match anything, a link past its date and
a link already used, and the API says which. The "account already exists" path was removed earlier
(bug 101).

**Proof.** Live on ACME: clipped → *"That link is not complete…"*; backdated expiry → *"This link
has expired."*; backdated use → *"This link has already been used."*; whole link → 200 twice. Suite
**1153**.

## 107. The whole Studio was pinned to a 1126px column, and the footer link was clipped

**Cause.** A leftover Vite starter rule, `#root { width: 1126px; margin: 0 auto; text-align: center }`,
wrapped the entire application: a narrow strip in the middle of a wide screen, and "Privacy" cut to
"Privac".

**Fix.** `#root` is full width and left-aligned; the shell owns the layout.

**Proof.** Live: `document.documentElement.scrollWidth <= window.innerWidth` at 1600px, footer reads
"Powered by Trendi · Privacy". Guard test mutated back to 1126px and watched to fail. Suite **1160**.

## 108. Guessed theme token names left white numbers on a white background

**Cause.** The first version of the new shell used `--color-bg` / `--color-text`, which do not
exist in this design system (it defines `--color-background-body`, `--color-background-card`,
`--color-background-surface`, `--color-text-primary`, `--color-text-secondary`). The page rendered
white behind dark cards and the KPI numbers were invisible.

**Fix.** The shell binds to the real tokens, so it follows the chosen light/dark mode.

**Proof.** Dark and light screenshots both legible; `test_the_footer_link_cannot_be_clipped` and the
width guard in `tests/test_studio_shell.py`. Suite **1160**.

## 109. Onboarding only celebrated if the customer authorised everything

**Cause.** The confetti hung off `CHANNELS.every(channel => authorised)`, and the Permissions page
had no Continue button, so a business that declined any capability finished setup with no
celebration and no obvious way onward.

**Fix.** Permissions now ends with an explicit **Continue** that fires the confetti regardless of
what was granted (or nothing), then opens the workspace. The all-decided trigger is kept.

**Proof.** Live on ACME with **0 of 7** permissions authorised: Continue → confetti canvas appears,
cleans up. Guard mutated (removed `celebrate()`) and watched to fail. Suite **1163**.

## 110. Sub-pages still pinned themselves to a narrow column

**Cause.** Each page kept its own `maxWidth: 1040, margin: 0 auto` wrapper after the shell was
fixed, so Quotes, Reports, Products and the rest stayed narrow and centered.

**Fix.** All wrappers removed; pages fill the content area. Bare empty states replaced with
`c-empty` blocks that give advice.

**Proof.** Ten pages visited in a real browser at 1600×1000 with **no horizontal overflow**; guard
fails if `maxWidth: 1040` returns. Suite **1163**.

## 111. Social (and any lazy page) went blank after a deploy

**Cause.** Assets had no cache headers and deploys used `rsync --delete`, so a window opened before
a deploy asked for a hash that had just been deleted. The lazy import rejected and React unmounted
the tree, leaving an empty page.

**Fix.** Assets are cached `immutable`; deploys keep old chunks (pruned after 7 days); the app
reloads once on `vite:preloadError`; an `ErrorBoundary` shows "That page did not load" + Reload.

**Proof.** Blocked the real Social chunk with a 404 → auto-reload, page renders. Social renders 1,009
chars normally. Guard: `test_a_stale_build_shows_a_message_not_a_blank_page`.

## 112. "Social service unavailable" while `docker ps` showed social healthy

**Cause.** social uses `network_mode: service:api`; recreating api alone stranded it on a dead
namespace, so the api could not reach 127.0.0.1:4390.

**Fix.** `scripts/vps/redeploy-api.sh` always recreates `api social` and then proves social answers.

**Proof.** Provider start endpoints returned 503 before, 200 after; all seven providers enabled.
Guard: `test_assets_are_cacheable_and_old_chunks_are_not_deleted`.

`SOCIAL_MEDIA_AND_BLANK_PAGES_2026-11-14.md`. Not fixable from this repository.

## 115. Media page printed Cloudflare's error page at the customer

**Cause.** A 200-second render wait exceeded Cloudflare's ~100-second origin limit, so the edge
served its own HTML; and six pages each had their own fetch helper, so the first fix missed five.

**Fix.** 85-second deadline with honest messages; one shared `api.ts`/`describeFailure()`.

**Proof.** Forced a 520 with Cloudflare's HTML: friendly sentence shown, zero "Cloudflare". Guard:
`test_media_rendering_finishes_before_the_edge_gives_up` (mutated to 200s and watched to fail).
