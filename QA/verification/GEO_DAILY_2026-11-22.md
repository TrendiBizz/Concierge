# GEO daily — Cloudflare CSP nonce made every page look changed (2026-11-22)

## Symptom

`python3 scripts/seo/geo-daily.py` reported `changed since last run: 44` on both 2026-11-21 and
2026-11-22 — i.e. every URL in the sitemap — and therefore re-pinged IndexNow for the whole site
on both days. 2026-11-19 and 2026-11-20 had reported `0`.

## Cause

Cloudflare now stamps a **fresh CSP `nonce="…"`** on its Web Analytics beacon script
(`static.cloudflareinsights.com/beacon.min.js`) on every request. The page fingerprint added on
2026-11-17 strips the challenge script by markers (`__CF$cv$params`, `cdn-cgi/challenge-platform`)
but the beacon script is not one of those markers, so its per-request nonce stayed in the hashed
text. Measured directly: two fetches of `https://trendibizz.com/` seconds apart produced
`ec8d088521226b13` and `f194e2960c3786f8`. The whole-site IndexNow submission that followed is
exactly the spam signal the 2026-11-16 fix was written to prevent.

## Fix

`scripts/seo/geo-daily.py`

1. `"cloudflareinsights.com/beacon"` added to `CF_MARKERS`, so the beacon script is dropped with
   the rest of Cloudflare's injections.
2. `NONCE = re.compile(r'\snonce="[^"]*"')`; `fingerprint()` strips every `nonce` attribute before
   hashing. A CSP nonce is never page content, so this is safe for any element Cloudflare stamps
   (script, style, link).

## Test

`api/tests/test_geo_daily.py` — the fixture now serves the page with the challenge script, the
analytics beacon and a `<style nonce>`, each carrying a per-request nonce, and `page()` gives the
clean version.

- `test_fingerprint_ignores_the_cloudflare_analytics_nonce`
- `test_fingerprint_ignores_a_fresh_ray_and_nonce_together`
- existing challenge-script/content-change/dateModified tests still assert real edits are noticed

Red without the fix (both markers removed → 3 failed, 3 passed), green with it (6 passed).
